# 时间管理小精灵（TimeManagementElf）跨平台架构与任务列表扩展开发文档 v0.2

## 一、更新背景与目标
- 在 v0.1 文档基础上，补充“任务列表”模块设计与跨平台适配方案，力求以最少的重复开发覆盖 iOS、Android、Web、Windows、macOS。
 - 继续满足：桌面宠物（多状态动画）、番茄钟（5/10/25/30 分钟与任务类型）、数据记录（番茄钟 CSV）。
- 移动端（iOS/Android）不包含宠物系统，仅提供任务列表与番茄钟的时间管理功能。
- 任务数据以服务器为唯一真源（Source of Truth）：所有任务通过后端数据库同步；每个用户拥有独立任务集合（逻辑隔离，建议物理上通过 `user_id` 字段与索引实现）。

## 二、技术选型（单代码库优先）
### 主方案：Flutter（Dart）
- 覆盖平台：iOS / Android / Web / Windows / macOS（官方支持）。
- 优点：单代码库；组件与动画生态完善；良好的桌面/移动适配能力；可通过 Platform Channel 实现桌面宠物所需的窗口控制。
- 动画方案：
  - Lottie（lottie_flutter）
  - SpriteSheet（自定义帧动画）
  - Rive（实时矢量动画）
- 文件与存储：
  - path_provider（移动/桌面文件路径）
  - dart:io 写入 CSV；Web 端使用 IndexedDB 存储并支持导出 CSV

### 替代与增强（按需）
- 桌面端：若需要更强的透明窗口与点击穿透支持，可考虑 Electron/Tauri 专用桌面宠物壳体，但优先尝试 Flutter 插件与原生通道。

## 三、跨平台适配策略
### 1) 桌面宠物
#### Windows/macOS（Flutter 桌面）
- 始终置顶：`window_manager.setAlwaysOnTop(true)`
- 透明窗口：使用 `flutter_acrylic` 或原生窗口样式实现透明背景；动画资源为 PNG/Lottie/Rive，确保无边框。
- 点击穿透：通过 Platform Channel 调用原生 API（Win32: `SetWindowLong`/`WS_EX_TRANSPARENT`；macOS: `NSWindow` `ignoresMouseEvents`）在非交互区域实现点击穿透；交互热区保留点击能力（喂食/喝水等）。
- 可拖动：自定义可拖动区域或模拟拖动事件。

#### iOS/Android（移动端不含宠物）
- 移动端不提供宠物系统，仅保留任务列表与番茄钟功能。
- 宠物相关 UI/代码通过平台判断剔除（如 `kIsWeb` / `Platform.isWindows` / `Platform.isMacOS`）。
- 导航：提供任务列表与番茄钟的入口（底部导航或悬浮按钮）。

#### Web
- 浏览器页面内悬浮宠物组件（Canvas/SVG/Rive/Lottie），不支持系统级置顶。

### 2) 数据记录（CSV）
#### 桌面/移动
- 路径：
  - Windows：`%APPDATA%/TimeManagementElf/data/`
  - macOS：`~/Library/Application Support/TimeManagementElf/data/`
  - iOS/Android：应用文档目录（`path_provider getApplicationDocumentsDirectory`）。
- 写入：首次写入生成表头，其后追加；并发通过写入队列串行化。
- 同步：客户端以服务器为真源，本地仅缓存与离线队列；网络恢复后自动提交并拉取增量。

#### Web
- 存储：IndexedDB（`idb_shim`/`drift` web backend）保存结构化记录。
- 导出：按需生成 CSV 字符串并触发下载（`Blob` + `a[href]`）。
- 同步：登录后与服务器双向同步，IndexedDB 作为本地缓存与离线操作队列。

### 3) 统一事件总线
- 采用 Riverpod/Bloc/EventBus 统一分发：
  - 任务选择 → 启动番茄钟 → 宠物状态联动；
  - 番茄钟结束 → 记录写入 → 宠物奖励动画。

## 四、模块设计（含任务列表）
### 1) 任务列表模块
#### 功能
- 列表展示：任务名称、类型、优先级、预计时长、标签、状态（待办/进行中/已完成）。
- 选择任务启动番茄钟：任务行上的“开始计时”按钮或进入详情后启动；默认时长可来自任务配置或通用设置。
- 增删改查：新增任务、编辑字段、标记完成、软删除/归档。
- 排序与过滤：按优先级、类型、标签、创建时间排序与筛选。
 - 预计与实际对比：任务的 `estimate_minutes` 为预估长度；实际耗时由番茄会话 `actual_minutes` 累计得到，用于对比与生成统计报表。

#### 存储与同步策略
- 服务器为唯一真源：所有任务 CRUD 操作通过后端 API 完成；客户端维护本地缓存（DB/IndexedDB）以提升体验。
- 离线支持：操作采用 Outbox 模式入队；网络恢复后按顺序提交；冲突通过版本号或 `updated_at` 比较解决（默认 Last-Write-Wins，可选乐观锁）。
- 导出：客户端或服务器端支持导出 `tasks.csv`；推荐由服务器侧提供导出接口以支持大数据量与审计。

#### 与番茄钟联动
- 启动番茄钟时记录当前任务 `task_id`；结束后写入番茄记录并回写任务统计（累计专注分钟、完成次数等）。

### 2) 番茄钟模块（扩展）
- 时长：5/10/25/30 分钟；可自定义；与任务类型关联（映射到不同提醒或宠物反馈）。
- 操作：开始/暂停/恢复/重置；结束提醒（音效/系统通知/本地推送）。
- 计时精度：以实际时间差为准（`DateTime.now` 差值 + `Ticker` 修正）。
- 同步：番茄会话记录在本地生成后即推送服务器（包含 `user_id` 与 `task_id`）；失败则进入离线队列，重试直至成功。
 - 统计口径：每次会话结束写入 `actual_minutes`（实际耗时），并可附带 `planned_minutes`（本次计划时长）；任务侧统计实际总耗时与会话次数。

### 3) 桌面宠物状态机（与 v0.1 保持一致并增强）
- 状态：`idle` / `sleep` / `jump` / `hungry` / `thirsty` / `eat` / `bored` + `focus`（番茄进行中）+ `reward`（番茄完成）。
- 变量：`energy` / `hunger` / `thirst` / `mood` / `idleTime`；任务驱动 `mood` 提升或降低。
- 交互：喂食/喝水/唤醒；点击宠物触发随机回应；任务完成触发奖励动画与音效。



## 后端与同步架构（新增）
### 技术栈建议
- 后端：Node.js（NestJS/Express）或 Go（Gin/Fiber）。
- 数据库：PostgreSQL（推荐）或 MySQL。
- ORM：Prisma / TypeORM。
- 鉴权：JWT（Access + Refresh）或 OAuth2。
- 实时：WebSocket / SSE（任务更新推送、番茄完成广播）。

### API 设计（示例）
- Auth
  - POST `/api/auth/login` { email, password }
  - POST `/api/auth/refresh`
- Tasks
  - GET `/api/tasks`
  - POST `/api/tasks` { title, task_type, priority, tags, estimate_minutes }
  - PUT `/api/tasks/{task_id}` { ... , version }
  - PATCH `/api/tasks/{task_id}/complete` { summary }
  - DELETE `/api/tasks/{task_id}`
- Tomato Sessions
  - GET `/api/tomatoes`
  - POST `/api/tomatoes` { task_id, planned_minutes, started_at, ended_at, status, interruption_reason }
- Export
  - GET `/api/export/tasks.csv`
  - GET `/api/export/tomato_clock.csv`
  - GET `/api/export/tasks_summary.csv`

### 同步流程（客户端）
1. 登录后拉取增量：`GET /api/tasks?since=last_sync_at`。
2. 本地改动入 Outbox 队列；后台/前台定时批量提交。
3. 冲突处理：使用 `version` 或 `updated_at` 比较；默认 LWW，必要时提示用户选择合并方案。
4. 成功后更新本地缓存与 `last_sync_at`。
5. 统计更新：会话结束或任务完成后，更新任务的累计实际耗时与会话次数；任务完成时提交 `summary`。

### 安全与隐私
- 所有请求需附带 Access Token。
- 审计：记录 `created_by`、`updated_by`、`ip`（可选）。

### 数据库表字段（Tasks）
- 表：`tasks`
  - `task_id` PK（UUID）、`user_id`（索引）
  - 业务字段：`title`, `task_type`, `priority`, `tags`, `estimate_minutes`
  - 状态字段：`status`, `completed_at`
  - 统计字段：`stats_focus_minutes`, `stats_actual_minutes`, `stats_sessions_count`
  - 总结字段：`summary`（任务完成总结，必填）
  - 同步/并发：`version`, `created_at`, `updated_at`

## 五、数据模型（CSV 字段建议）
### 1) 任务列表（`tasks.csv` 或 DB 同步导出）
- `task_id`（UUID）
- `user_id`（UUID）
- `title`（字符串）
- `task_type`（字符串，如写作/阅读/编码）
- `priority`（`low`/`medium`/`high`）
- `tags`（逗号分隔）
- `estimate_minutes`（整数，可空）
- `created_at`（ISO）
- `updated_at`（ISO）
- `completed_at`（ISO，可空）
- `status`（`todo`/`in_progress`/`done`/`archived`）
- `stats_focus_minutes`（累计专注分钟，整数）
 - `version`（整数，自增，用于冲突检测）
 - `stats_actual_minutes`（累计实际耗时，整数）
 - `stats_sessions_count`（累计会话次数，整数）
 - `summary`（任务完成总结，文本；当 `status=done` 时必填）

### 2) 番茄钟记录（`tomato_clock.csv`，与 v0.1 一致并增加 `task_id`）
- `session_id`, `user_id`, `task_id`, `task_type`, `planned_minutes`, `actual_minutes`, `started_at`, `ended_at`, `status`, `interruption_reason`

### 任务统计与报表（导出 `tasks_summary.csv`）
- 字段示例：
  - `task_id`, `user_id`, `title`, `task_type`, `estimate_minutes`, `actual_total_minutes`, `sessions_count`, `avg_session_minutes`, `variance_minutes`, `completed_at`
- 计算口径：
  - `actual_total_minutes` = 所有关联会话 `actual_minutes` 之和
  - `sessions_count` = 关联会话数量
  - `avg_session_minutes` = `actual_total_minutes` / `sessions_count`
  - `variance_minutes` = `actual_total_minutes` - `estimate_minutes`
  - 统计由服务器或客户端生成；服务器生成更适合大数据量与审计。

## 七、UI 与交互草案（新增任务列表）
### 任务列表页
- 顶部：任务类型筛选、标签筛选、排序选择（优先级/创建时间）。
- 列表项：标题、类型、优先级、预计时长、状态；操作按钮：开始计时、编辑、完成、更多。
- 新建任务：弹窗或独立页，支持任务类型、时长、标签、优先级输入。
 - 完成任务：弹出“任务总结”编辑框，提交后调用 `PATCH /api/tasks/{task_id}/complete { summary }` 并更新统计。

### 番茄钟面板
- 显示当前任务标题与类型；选择 5/10/25/30；开始/暂停/恢复/重置；结束提醒。

### 宠物悬浮窗
- 与番茄钟联动显示 `focus/reward` 状态；右键菜单（桌面）：喂食/喝水/设置；Web：页面内悬浮按钮打开控制面板；移动端不提供宠物悬浮窗。

### 移动端（iOS/Android）界面
- 不包含宠物系统，仅提供任务列表与番茄钟。
- 推荐底部导航：Tab1 任务列表 / Tab2 番茄钟 / Tab3 设置。
- 番茄钟完成后触发系统通知/本地推送与数据记录；不触发宠物动画。

## 八、计时精度与后台策略
- 桌面/移动：使用 `Ticker` + `DateTime` 差值，避免 timer 漂移；后台/锁屏时使用系统通知或本地推送提醒。
- Web：页面非活跃时使用 Visibility API 与时间差校正；不可用时回退为结束时校验。

## 九、CSV 写入与导出实现要点
### 统一 CSV writer
- 首次写入表头；后续逐行追加；异常记录 `error.log`。
- 并发写入通过队列串行；避免文件锁竞争。

### Web 端
- 不做实时文件写入，使用 IndexedDB 存储；导出时生成 CSV 并下载；可提供“自动每 N 次记录提示导出”。
